# Project working rules

- Read docs/inventory-console/README.md, then the relevant task in 07-MILESTONES-AND-TASKS.md and its source documents before changing code.
- Preserve the six original documents. Update progress and verification with actual evidence; do not replace the plan with an invented completion claim.
- Use TDD for behavior changes: observe a relevant failing test, implement the smallest fix, verify Green, then refactor if needed. Follow 08-TDD-WORKFLOW.md and keep concise evidence.
- Keep PR descriptions and reviews in short, simple English. Assign every PR to DevvMa. Use focused branches, Conventional Commits, required CI, and squash merge under 09-GIT-WORKFLOW.md.
- The owner authorized agent review and merge for this project. Review the actual final diff and wait for required CI on the final head; do not bypass main protection. This does not authorize deployment.
- Use evidence for factual claims. Label facts, synthesis, and assumptions separately in user-facing answers. Test or clarify assumptions.
- Do not control native apps or browsers without consent. The owner allowed the internal browser for project checks. Its control tool failed at startup twice; permission for a separate test browser is pending. See 13-BROWSER-CHECK.md before continuing browser work.
- Do not claim browser, visual, accessibility, or owner-understanding verification from code tests alone. T25 and T29 require their own evidence/input.
